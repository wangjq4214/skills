# Refactoring and batch evidence

Read for quantitative simplification, refactoring, or batch assignments; the main skill's permissions still apply. No map, ledger, or formal plan becomes mandatory.

Use supplied scope, base/current revision or fingerprints, preserved contracts, criteria, and integrated validation evidence. Read source behind map/worker claims; branch-local evidence is not automatically valid for the combined tree.

For quantitative or comprehensive simplification, assess each requested criterion separately: behavior preservation, coverage, responsibility separation, semantic reuse, readability, obsolete-code removal, and any LOC target. Tests passing does not establish structural improvement or a size target.

Reproduce baseline/final counts with the same scope, counter, filters, and formatting. Include new/moved implementations and inspect transfers into config/generated code/dependencies. A smaller largest file does not establish net code reduction. Preserve each target's source and aspirational/required status; a coordinator's default 30% aspiration is not a user-required gate. Do not invent a target or promote an aspiration into a requirement.

A measured missed required threshold is a gap. A missed aspirational target is a reported shortfall, not a blocking gap or reason by itself to withhold acceptance; do not claim it achieved. Unavailable or incomparable measurements are needs-verification, never fabricated success. Return criterion-to-evidence results, target outcomes, snapshot, commands/results, coverage gaps, and proposed status transitions. A local result cannot mark the whole request complete.
