# Refactoring and batch evidence

Read for quantitative simplification, refactoring, or batch assignments; the main skill's permissions still apply. No map, ledger, or formal plan becomes mandatory.

Use supplied scope, base/current revision or fingerprints, preserved contracts, criteria, and integrated validation evidence. Read source behind map/worker claims; branch-local evidence is not automatically valid for the combined tree.

For quantitative or comprehensive simplification, assess each requested criterion separately: behavior preservation, coverage, responsibility separation, semantic reuse, readability, obsolete-code removal, and any LOC target. Tests passing does not establish structural improvement or a size target.

Reproduce baseline/final counts with the same scope, counter, filters, and formatting. Include new/moved implementations and inspect transfers into config/generated code/dependencies. A smaller largest file does not establish net code reduction. Do not impose 30% or any other target absent from the user's scope.

A measured missed target is a gap; unavailable or incomparable measurements are needs-verification. Neither becomes match because a plan was followed. Return criterion-to-evidence results, counts, snapshot, exact shortfalls, commands/results, coverage gaps, and proposed status transitions. A local result cannot mark the whole request complete.
