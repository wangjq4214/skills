# Refactoring and batch evidence

Read for refactoring, batch, or integrated-tree assignments; the main skill's permissions still apply.

Record base/current revision or fingerprints, changed paths, preserved contracts, and relevant consumers. Use map shards only for navigation and revalidate source claims. Review actual diffs, including deletions and neighboring behavior, rather than worker summaries.

Partition by risk/subsystem with inspected/partial/unread coverage; independent lenses may overlap. Examine cross-unit seams after integration: shared-helper semantics, error/route precedence, registration reachability, state ownership, dependency cycles, and public compatibility.

A smaller file, LOC reduction, or successful merge does not prove improved architecture. Check whether understanding is simpler rather than hidden behind wrappers, flags, or a universal context.

Return findings tied to the reviewed snapshot, checks, coverage gaps, and unresolved evidence. Reassess affected branch findings after integration or conflict resolution; do not promote a branch review into a global clean result.
